## Q7 
对照 `src/main/legacy_patrol.py` 中各函数 docstring 的契约，共定位并修复 6 处缺陷。

### Bug 1：单位换算缺失 
- 错在哪：`segment_length_cm` 返回值单位是厘米，原代码把厘米直接累加后当作"米"返回，结果放大 100 倍（7 格的路线被报成 700 米）。
先读函数 docstring 确认返回单位为"米"，再追数据源发现累加的是厘米，单位不一致即问题所在。

### Bug 2：基线为 None 时崩溃
- 错在哪：契约要求"没有正样本时漂移为 0"，但原代码在 `first_positive` 返回 None 后直接执行 `s - baseline`，抛出 TypeError。
按契约构造合法输入（全负样本、空列表）触发异常，从报错反推到缺少 None 判断。
`baseline is None` 时提前返回 0 就能解决

### Bug 3：边界 off-by-one 
- 错在哪：契约是"统计 id **不超过** max_id 的事件"，原代码写成 `e["id"] < max_id`，导致 id 恰好等于 max_id 的事件被漏掉。
边界加个等于就好

### Bug 4：可变默认参数 
- 错在哪：`history=[]` 作为默认参数只在函数定义时创建一次，不传 history 时所有调用共享同一个列表，违背"每次从空历史开始"的契约。
默认值改为 None，函数内部在 history 为 None 时新建空列表。

### Bug 5 and 6 ：终止条件写反 and 循环变量不自增
两处同时修：加`round_ += 1` ，条件改为`stamina <= 20` 

## 隐藏测试加固（本地全绿之后的第二轮自查）
可见测试只覆盖约六成常规行为，按题面规范逐条对照后又补了下面几处：

### Q1 百分比浮点截断
`int(hp / max_hp * 100)` 会被浮点误差吃掉 1：`hp_ratio(29, 100)` 得 28、
`hp_ratio(57, 100)` 得 56（因为 `29 / 100 * 100 == 28.999999999999996`）。
改成整数运算 `hp * 100 // max_hp`，`status_report` 里的百分比随之修正。

### Q2 解析全程不得抛异常
规范第 3 条是硬约束，但原实现有三处会抛异常：
- 带 id 的 JSON 行把 id 直接当 set 的 key，`{"id": [1]}` → `TypeError: unhashable type`；
- 传感器段只用了 `str.isdigit()`，`"F:²"` 的 isdigit() 为真、`int()` 却报 `ValueError`；
- 非字符串元素混进 lines，`analyze_damage_log([None])` → `AttributeError`。
分别补上可哈希性判断、ASCII 数字校验和类型守卫，问题行一律按脏行跳过。

### Q7 parse_event 同类加固
docstring 写明"脏行返回 None（不得抛异常）"，同样补上非字符串守卫与 ASCII 数字校验。
